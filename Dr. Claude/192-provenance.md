# Brief 192 (provenance hunk only) — Build provenance: startup log + accessor

**Repo:** JakeTunesV3 · **Patch:** `patches/brief-192-provenance.patch` (index.ts chain, position #4 — apply last) · **Branch:** `fix/brief-192-provenance` (stacked on chain B)

## Scope

Brief 192 has two halves. The root-bundle/CI half (move/stamp the
stale root `index.js`, CI check) is **another worker's PR**. This
patch is only the provenance half the brief asks the main process
for: "the version endpoint/startup log reports build provenance
(commit SHA + build time)".

## What the patch does

- **New module `src/main/build-provenance.ts`** —
  `getBuildProvenance(version, dir?)` reads `build-info.json`
  (generated by the companion PR's build tooling) from beside the
  bundled main, defensively: absent, unparseable, or shapeless →
  `{ version, buildSha: 'dev', builtAt: null }`. It never throws —
  a dev run or a damaged stamp must not break boot.
  `formatBuildProvenance()` renders the shared one-line form:
  `JakeTunes 6.0.0 (build 12bb43b24d49, built 2026-10-14T…)` or
  `JakeTunes 6.0.0 (build dev)`. The accessor (`getBuildProvenance`)
  is the export Brief 195's parity payload consumes.
- **index.ts hunk** (+5): import the module, and one startup log
  line right after `boot.main-start`:
  `console.log('[boot] ' + formatBuildProvenance(getBuildProvenance(app.getVersion())))`
  — which the flight recorder's console mirror also lands in
  main.log.
- No version bump (per CLAUDE.md versioning rules), no change to
  the existing `get-app-version` IPC.

Dependency: until the companion PR's generator lands, packaged
builds simply report `dev` — the reader degrades by design, so
the two halves can merge in either order.
